Motivation
The Symmetric Bottleneck
Prior Work — Prio · Prio+ · Elsa

Prio is the bedrock of several practical deployments (Mozilla, Apple/Google/ISRG)

Incurs symmetric cost on Both Servers

Both servers must process O(L) data, where L is the model dimension. In modern deep learning L ≈ 107 parameters, making the secondary server prohibitively expensive to operate.

  • Abort is indistinguishable from client misbehaviour
  • Server-side comm. scales with L, not client count n
TAPAS — Our Approach

Intentional Asymmetry

One server bears the full O(L) aggregation load; the other is a lightweight facilitator whose cost is independent of L and scales only with the number of clients n.

  • Post-quantum: LWE + SIS only
  • Identifiable Abort: faults are cryptographically attributed
  • No trusted setup or preprocessing

Input Validation
Two ZKP Instantiations

To guarantee clients' inputs satisfy norm constraints (L2 / L∞), TAPAS offers two proof systems with complementary trade-offs.

TAPASBP — Bulletproof Variant

Group-Based Proofs

  • Pedersen commitments + Bulletproofs over prime-order group
  • Building on prior works of GHV21, ACORN, Armadillo
  • Four-square theorem proves L2 / L∞ norms exactly
  • Better than Heli's \( O(tL) \) expansion where \( \|\mathbf{x}\|_\infty\leq 2^t-1 \)
  • Limitation: group exponentiations expensive at large L
TAPASLWE — Lattice-Only Variant

All-Lattice Proofs

  • Proofs entirely over LWE modulus q — no extra group field
  • No group exponentiations whatsoever
  • Best asymptotic performance for large L
Technical Challenge
Three Lattice Caveats
Caveat 1

Rejection Sampling

Responses must be over the integers, not modulo q. We must sample carefully and abort if the response violates a norm bound — to prevent leaking the secret.

Caveat 2

Repetition Cost

Reducing rejection probability forces a smaller challenge space, which increases soundness error. More repetitions of the protocol are required to compensate.

Caveat 3

Soundness Slack

The witness can only be extracted with an error margin. For monolithic proofs over dimension L:

Slack \(\gamma \approx \sqrt{L}\)

This is the core bottleneck for large L.

Key Innovation
Independent Restarts — Closing the Security Gap
The Technique

Each block performs rejection sampling independently. If block 5 fails, only block 5 restarts — all other blocks keep their accepted values.

Expected Time: \(\mathcal{O}(k \cdot M)\) with \(M \approx 2\)

Transforms exponential-in-k convergence into linear, restoring practical efficiency for high-dimensional witnesses.

The Security Gap

Independent blocks open an attack: a malicious client could use different secrets sj per block to inject garbage. This breaks the global consistency guarantee.

Question: How do we enforce s1 = s2 = … = sk without reverting to O(L) communication for Server 2?

Answer: Cross-Server Digest Check

Server 2 re-derives responses using the client's single secret s, hashes them, and sends a 256-bit digest to Server 1 for verification. Communication overhead for S2 remains O(λ).

Malicious Security
PROM + Equivocable Commitments
The Simulation Trap

A malicious Server 1 drops ciphertexts dynamically. The simulator must commit to honest ciphertexts before knowing which clients S1 will drop — but it cannot query the ideal functionality without knowing the final online set.

The PROM Solution

Add a secondary programmable mask derived from a seed ρi:

\(y_i = As_i + e_i + \Delta x_i + \mathcal{H}'(\rho_i)\)

The simulator programs H′(ρi) after the online set is fixed, injecting a correction term into the sum.

The ZKP Dilemma

Proving correctness of yi now requires proving inside the ZKP that H′(ρi) was computed correctly — expensive and incompatible with the Programmable Random Oracle Model used for simulation.

Equivocation Technique

Commit directly to the raw mask w without proving its derivation. Use an equivocable commitment (Pedersen DL trapdoor or wide Ajtai SIS matrix) to re-open to wtarget after the online set is finalised.

\(\text{Prove } y_i \text{ w.r.t. } w \quad + \quad \text{Equivocal commitment to } w\)
Stronger Security Guarantee
Identifiable Abort
 1. Binding Handshake

Before exchanging any data, servers intersect their valid-client sets V1 ∩ V2 = V and each signs and broadcasts V. Neither server can later deny seeing a client's message.

 2. Proof of Malice

If a digest fails, the server must produce the original signed message as evidence. Because signatures are non-repudiable:

  • Server cannot fake a client error
  • Server cannot frame an honest client
 3. Privacy Guarantee

False alarms reveal the server as the cheater — without exposing any client secret.
