What is Gradient Boosting?

The idea

Build a model $\hat{y} = \sum_{t=1}^T f_t(x)$ by adding trees one at a time, each correcting the errors of all previous trees.

$\hat{y}_i^{(t)} = \hat{y}_i^{(t-1)} + f_t(x_i)$

Each new tree $f_t$ is fitted to the negative gradient of the loss — how much each prediction is wrong and in which direction.

The two key statistics

Gradient $g_i$

How wrong the current prediction is, weighted by class importance:

$g_i = w_i\bigl(\sigma(\hat{y}_i^{(t-1)}) - y_i\bigr)$

$w_i = w_+$ for positive (fraud) samples, $w_i=1$ for negative. $\sigma$ is the sigmoid function.

Hessian $h_i$

How curved the loss is — controls the step size:

$h_i = w_i\,\sigma(\hat{y}_i^{(t-1)})\bigl(1-\sigma(\hat{y}_i^{(t-1)})\bigr)$

Used to compute the optimal leaf value: $v_\ell = -\eta\, G_\ell/(H_\ell+\lambda)$

Notation used throughout: $G = \sum_i g_i$ (sum of gradients in a region)  ·  $H = \sum_i h_i$ (sum of Hessians)  ·  $\lambda$ = regularisation  ·  $\eta$ = learning rate

XGBoost: standard (non-oblivious) trees

Split selection at each node

For each candidate split $(f, \theta)$ — feature $f$, threshold $\theta$ — compute the gain:

$\text{Gain}(f,\theta) = \underbrace{\dfrac{G_L^2}{H_L+\lambda}}_{\text{left child}} + \underbrace{\dfrac{G_R^2}{H_R+\lambda}}_{\text{right child}} - \underbrace{\dfrac{G^2}{H+\lambda}}_{\text{parent}}$

where $G_L,H_L$ = gradient/Hessian sums for samples with $x^{(f)} \leq \theta$, and $G_R,H_R$ for $x^{(f)}>\theta$.

Each node independently picks the split maximising Gain$(f,\theta)$.

CatBoost: oblivious (symmetric) trees

The key constraint

All nodes at depth $d$ use the same split $(f_d, \theta_d)$.

$\ell(x) = \sum_{d=1}^{D} \underbrace{\mathbf{1}[x^{(f_d)} > \theta_d]}_{\text{0 or 1}} \cdot 2^{D-d}$

The leaf index is a $D$-bit binary number. Inference: $D$ comparisons + one table lookup = $O(D)$.

For federation: at depth $d$, we need exactly one split decision covering all $2^{d-1}$ existing leaves simultaneously → naturally $D{+}1$ aggregation rounds per tree.

CatBoost vs XGBoost on fraud: empirical evidence

Why oblivious trees generalise better

Regularisation via symmetry

Every split must justify itself across all current leaves, not just one node. Prevents memorising minority-class patterns at the expense of generality.

Balanced leaf coverage

All $2^D$ leaves populated by construction. XGBoost frequently collapses into lopsided structures on 1:2,685 imbalanced data.

No gradient leakage across depths

Oblivious splits decouple depth levels — overfitting at depth $d$ doesn't compound through subsequent depths as it does in non-oblivious trees.

The Privacy Challenge: why we can't centralise

The horizontal federation setting

$K$ organisations (banks, payment processors) each hold transaction data $\mathcal{D}_k = \{(x_i, y_i)\}$ with the same feature space.

They want to train a shared fraud model on the union $\bigcup_k \mathcal{D}_k$ without any raw data leaving their premises.

Legal constraints: GDPR, CCPA, HIPAA, and banking regulations prohibit sharing customer transaction records across organisational boundaries.

Federated Learning

Train collaboratively by sharing only model updates, not raw data.

Secure Aggregation (SecAgg)

Clients add secret zero-sum masks to their updates before sending. The server sums everything — masks cancel — and recovers only the aggregate:

$\textstyle\sum_k(v_k + m_k) = \sum_k v_k\;$ because $\;\sum_k m_k = \mathbf{0}$

No individual client value is ever visible to the server.

Goal: train a federated model matching or exceeding centralised CatBoost performance (ROC-AUC 0.962) — with full SecAgg protection and zero per-client leakage.

Federated XGBoost: FedTree [Li et al., MLSys 2023]

Core idea: aggregate histograms, not data

Instead of sharing raw samples, each client computes a local gradient histogram for each candidate split and sends it to the server.

Gradient histogram $\mathbf{h}_k^{(f,b)}$

For feature $f$, bin $b$ — the sums of gradients and Hessians for samples on client $k$ that fall in that bin:

$h_k^{(f,b)} = \Bigl(\sum_{i \in \mathcal{D}_k:\,b_f(x_i)=b} g_i,\;\sum_{i \in \mathcal{D}_k:\,b_f(x_i)=b} h_i\Bigr)$

$b_f(x_i)$ = the bin index of $x_i$ for feature $f$. $B$ bins per feature (typically 64).

Server aggregates via SecAgg: $\mathbf{h}_\text{agg}^{(f,b)} = \sum_k \mathbf{h}_k^{(f,b)}$, then selects the best split.

Layer-wise Batched Communication (LBC)

Without LBC: one network call per node. At depth $d$ this is $2^{d-1}$ calls. For depth 6: 63 calls per tree.

LBC packages all node histograms at a given depth into one network envelope. Reduces 63 TCP connections to $D=6$ connections per tree.

Important: LBC is purely a network engineering trick — it does not reduce the number of independent SecAgg computations. Each node still has its own separate masks. FedTree with LBC still runs $2^D{-}1 = 63$ SecAgg operations per tree.
Result: FedTree achieves accuracy identical to centralised XGBoost (their Table 1). But it trains XGBoost-style trees, not CatBoost-style oblivious trees.

The accuracy gap: FedTree matches XGBoost, not CatBoost

What FedTree achieves

FedTree replicates the XGBoost training algorithm in a federated setting. Li et al. (MLSys 2023) confirm it matches centralised XGBoost accuracy. This means it also inherits XGBoost's overfitting behaviour on imbalanced data.

FedTree (federated) $\approx$ XGBoost (centralised) $<$ CatBoost (centralised)
This gap is structural, not a privacy cost. FedTree trains non-oblivious trees — a different algorithm than CatBoost. No privacy-preserving engineering can replicate CatBoost accuracy with XGBoost tree structure.

Flower's Federated CatBoost: the bagging approach

① Server broadcasts
Sends current global model ($K{\times}r$ trees after round $r$) to all $K$ clients.
② Clients train locally
Each client trains 1 new tree using the global model's predictions as residuals: $$g_i = \sigma(\hat{y}_\text{global}(x_i)) - y_i$$
③ Clients return tree
Each sends 1 newly trained tree back to the server. (Variable-structure object, not a fixed-dim vector.)
④ Server concatenates
Appends all $K$ new trees. Model grows to $K(r{+}1)$ trees. Repeat.
Key insight: because clients compute residuals from the global model (not a local model), the gradients $g_i = \sigma(\hat{y}_\text{global}) - y_i$ are global residuals. This resolves the non-IID problem: each new tree corrects the global ensemble's errors, not just local errors. Each tree still trains on only $N/K$ samples.

Three problems with Flower's approach

1

Weak individual trees

Each tree is trained on $N/K$ samples.

To match centralised accuracy, need $\approx K{\times}$ more trees.

For $K=5$, $T=200$: Flower needs ~1,000 trees vs FedOBGDT's 200. 5× larger model, 5× slower inference.

2

No global stopping criterion

FedOBGDT: server computes global gain from aggregate histograms. Stops when gain $\leq 0$.

Flower: server never sees gradient statistics — no signal for convergence. Run for fixed rounds. Accumulate unnecessary trees.

3

Growing download cost

After $r$ rounds: model has $Kr$ trees.

Server sends all $Kr$ trees to every client at the start of each round. Download grows without bound.

Root cause: Flower aggregates trees. FedOBGDT aggregates gradient statistics. The aggregation point determines all three properties.

Why Flower's approach cannot use Secure Aggregation

SecAgg works through one algebraic property:

$\displaystyle\sum_k \bigl(v_k + m_k\bigr) = \sum_k v_k + \underbrace{\sum_k m_k}_{=\,\mathbf{0}} = \sum_k v_k$

Zero-sum masks $m_k$ cancel only when the aggregation is element-wise summation over fixed-dimension vectors. This is the one and only situation where masking protects privacy.

FedOBGDT: summation ✓

Clients send histogram vectors $\mathbf{h}_k \in \mathbb{R}^n$ — fixed dimension, same shape for all clients.

$\textstyle\sum_k(\mathbf{h}_k + \mathbf{m}_k) = \sum_k \mathbf{h}_k$

Masks cancel. Server sees only the aggregate. Individual contributions are hidden.

Flower: concatenation ✗

Clients send trees $T_k$ — variable structure (different splits, different leaf values). Not fixed-dimension.

Server builds $[T_1,\, T_2,\, \ldots,\, T_K]$. With masks: $[T_1{+}m_1,\, \ldots,\, T_K{+}m_K]$.

Masks do not cancel in concatenation — the algebraic property does not hold. Server must see individual trees.

Privacy is structurally impossible: server must inspect each tree to concatenate it.
API incompatibility: SecAgg requires fixed-dim vectors; trees have variable structure.

The fix: aggregate gradient
statistics, not trees.

Trees are the server's computation output — not client inputs.
This design choice restores:

  • ✓ SecAgg compatibility — clients send summable fixed-dimension vectors
  • ✓ Globally optimal splits — every tree uses all $N$ samples' gradient information
  • ✓ Principled convergence — server sees global gain and can stop when it drops below zero
  • ✓ Compact model — $T$ globally-optimal trees, not $KT$ locally-optimal ones

Oblivious trees: the mathematics of FedOBGDT

The oblivious split objective

At depth $d$ with $L = 2^{d-1}$ existing leaves, we must choose one split $(f, \theta)$ to apply to all leaves. The gain is:

$\mathcal{G}(f,\theta) = \sum_{\ell=0}^{L-1}\!\Biggl[\frac{G_{\ell,L}^2}{H_{\ell,L}{+}\lambda} + \frac{G_{\ell,R}^2}{H_{\ell,R}{+}\lambda} - \frac{G_\ell^2}{H_\ell{+}\lambda}\Biggr]$

$G_{\ell,L}$ = gradient sum for samples in leaf $\ell$ going left. $G_\ell = G_{\ell,L} + G_{\ell,R}$. Sum is over all $L$ leaves.

We select $(f^*,\theta^*) = \arg\max_{f,\theta}\,\mathcal{G}(f,\theta)$.

Because $\mathcal{G}$ sums over all leaves, it can be computed from per-leaf gradient histograms — which are summable across clients and can be SecAgg'd.

Compare to FedTree without LBC: needs $\sum_{d=1}^D 2^{d-1} = 2^D{-}1 = 63$ rounds per tree at $D=6$. FedTree with LBC reduces network calls to $D$ but still runs 63 SecAgg operations. FedOBGDT genuinely runs $D{+}1 = 7$ SecAgg operations.

Critical insight: the global histogram is provably wrong

The naïve approach

Instead of summing $G_{\ell,L}^2/(H_{\ell,L}{+}\lambda)$ over each leaf separately, use a single global sum $G_L = \sum_\ell G_{\ell,L}$:

$\underbrace{\dfrac{G_L^2}{H_L+\lambda}}_{\text{global (wrong)}} \;\;\leq\;\; \underbrace{\sum_\ell \dfrac{G_{\ell,L}^2}{H_{\ell,L}+\lambda}}_{\text{per-leaf (correct)}}$

This is the Cauchy-Schwarz inequality. Equality holds only when $G_{\ell,L}/H_{\ell,L}$ is constant across all leaves — generically false after depth 1.

Global histogram — what happens
  • Histogram is identical at every depth: same samples, same $g_i$, $h_i$ values
  • $\mathcal{G}(f,\theta)$ from global histogram is identical at every depth
  • Same split $(f^*,\theta^*)$ chosen at $d=1, 2, \ldots, D$
  • Only 2 of $2^D=64$ leaves are ever populated
Per-leaf histograms — what happens
  • At depth $d$: $L = 2^{d-1}$ separate histograms, one per leaf
  • Stacked into one vector and SecAgg'd — one round per depth
  • Different split chosen at each depth level
  • 74.8% of 64 leaves populated

FedOBGDT Phase 0: Secure Setup (bin edges & base score)

Phase 0a: Bin Edge Construction

We need to discretise the feature space into $B=64$ bins — but without revealing each client's data distribution.

Server specifies
Announces coarse feature ranges $[l_f, u_f]$ from domain knowledge. No client input needed.
Dense grid
Proposes $G=10{,}000$ uniform grid points over $[l_f, u_f]$ per feature.
Clients mask & send
Each client counts samples per grid cell → integer vector $\mathbf{c}_k \in \mathbb{Z}^G$. Adds SecAgg mask. Sends $\tilde{\mathbf{c}}_k$.
Server aggregates
Sums masked integers (masks cancel). Steps through CDF, places bin edge every $1/B$ of total data.
No client ever sends any unprotected information. The server learns only the aggregate count distribution.

Phase 0b: Base Score

The base score $\hat{y}_0 = \log\!\bigl(w_+ \cdot \text{fraud\_rate}\bigr)$ requires knowing the global fraud rate.

Each client computes $(n_\text{pos}, n_\text{total})$ — counts of fraud and all samples — adds a SecAgg mask, and sends masked integers.

$\hat{y}_0 = \log\!\!\left(\frac{w_+\sum_k n_{\text{pos},k}}{\sum_k n_{\text{total},k}}\right)$

Server broadcasts. All clients initialise predictions at $\hat{y}_0$.

Communication cost of Phase 0: each client sends $F \times G = 112 \times 10{,}000 = 1.12$M masked integers (8.96 MB) plus 2 integers for the base score. One-time cost.

Compound bin-ID: $O(2^d \cdot F) \to O(F)$ per depth

Naïve: $L$ separate passes
for ℓ in range(L):        # L = 2^(d-1) leaves
  for f in features:      # F = 112 features
    mask = (leaf_id == ℓ)
    bincount(bins_f[mask],
             weights=g[mask])
# ⟹ L × F = 32 × 112 = 3,584 calls at depth 6
# ⟹ O(2^d · F · Nₖ) operations
Compound bin-ID: 1 call per feature

Encode leaf and bin in one integer: $c_f(x) = \ell(x) \cdot B_f + b_f(x) \;\in\; \{0,\ldots,L B_f - 1\}$ 

for f in features:
  bincount(compound_id_f,     # c_f for all samples
           weights=g,
           minlength=L * B_f
  ).reshape(L, B_f)           # per-leaf histogram matrix
# ⟹ 1 × F = 112 calls (any depth)
# ⟹ O(F · Nₖ), independent of L
Speedup: ~3× empirical improvement — 40 s/tree → 13 s/tree (4M samples, 5 clients, $D=6$, $F=112$). Zero approximation error.
Why it works: since $b_f(x) < B_f$, the decomposition $j = \ell \cdot B_f + b$ is unique. Entry $j$ of the bincount accumulates exactly $G_{\ell,f,b}$. Reshape recovers the $(L \times B_f)$ matrix.

What does the aggregate histogram contain?

Round 1 (tree $t=1$)

All samples share base score $\hat{y}_0$. Gradients take exactly two values, determined by label only:

Fraud ($y_i=1$):   $g = w_+(\sigma(\hat{y}_0) - 1) < 0$
Legit ($y_i=0$):   $g = \sigma(\hat{y}_0) > 0$

Since $p_0 = \sigma(\hat{y}_0)$ and $w_+$ are public, the aggregate $G_{\ell,f,b}$ encodes the joint label distribution per cell — the server can infer the fraction of fraud samples in each histogram bin.

Rounds $t > 1$

After each tree, predictions $\hat{y}_i$ diverge across samples. Gradients become residuals:

$g_i \approx \sigma(\hat{y}_i^{(t-1)}) - y_i \quad \text{(model-dependent)}$

No longer a simple function of $y_i$. The histogram still reveals which feature bins correlate with model errors, but the mapping to raw labels is no longer direct. Leakage decreases as the model improves.

What SecAgg reveals: only the aggregate sum $\sum_k \mathbf{h}_k$ — the intended output of the protocol. This encodes joint data statistics, identical to what centralised CatBoost uses for training. No per-client breakdown is ever visible to the server.

Privacy: what SecAgg protects vs what DP protects

SecAgg protects ✓
  • Individual client contribution $\mathbf{h}_k$ — never visible to server
  • Which client holds which samples
  • Per-client fraud rate and feature distributions
  • Any per-client statistic whatsoever

SecAgg is the core privacy guarantee — FedOBGDT is designed to be SecAgg-compatible by construction.

Differential Privacy (DP) additionally protects ✓
  • Individual records from the aggregate — even from the sum itself
  • Membership inference: was sample $i$ in the training data?
  • Statistical reconstruction from aggregate histograms

DP protects individuals from what SecAgg intentionally reveals (the sum). These are complementary, not competing.

The hierarchy: Without SecAgg → server sees per-client histograms (worst). With SecAgg only → server sees aggregate sum; individual clients protected. With SecAgg + DP → even individual records are protected from the aggregate. FedOBGDT currently provides the middle tier; DP can be added as a one-line extension.

Adding Differential Privacy to FedOBGDT

Mechanism

After integer SecAgg aggregation, add calibrated discrete Gaussian noise to the aggregate before dequantisation:

$\hat{\mathbf{h}}_\text{agg} \;\leftarrow\; \sum_k \hat{\mathbf{h}}_k \;+\; \mathcal{N}_\mathbb{Z}(0, \sigma^2)$

then dequantise: $\mathbf{h}_\text{agg} \leftarrow \hat{\mathbf{h}}_\text{agg} / \alpha$

Noise is added in the integer domain, preserving SecAgg compatibility. One line of code change.

Sensitivity analysis

$\Delta_2 = C\sqrt{F} \approx 30\sqrt{112} \approx 317$
$C$ = gradient clip value, $F$ = number of features

Each sample contributes to exactly one bin per feature, so the $\ell_2$ sensitivity across the full histogram vector is $C\sqrt{F}$, not $C\sqrt{FB}$.

Why FedOBGDT generalises better

Oblivious tree regularisation

Every split is chosen to maximise gain across all leaves simultaneously — a symmetric constraint that prevents fitting a single outlier leaf.

Federated implicit regularisation

Each round, gradient statistics are summed across $K=5$ partitions. The per-partition noise acts as a form of stochastic gradient regularisation.

Fewer bins (64 vs 256 for XGBoost)

Coarser binning prevents individual fraud samples from creating isolated high-precision leaf regions — a known source of overfitting on rare events.

Conclusions

FedOBGDT beats centralised models on generalisation

ROC-AUC 0.970 — best of three, exceeding centralised CatBoost (0.962) and XGBoost (0.949). Recall@1% review: 73.7% vs 71.8% (CatBoost) vs 68.4% (XGBoost). Privacy comes for free — it actually helps.

Per-leaf histograms: the only correct abstraction

Cauchy-Schwarz proves the global histogram is wrong (collapses to ≤2 leaves). Per-leaf protocol recovers full oblivious tree structure with 74.8% leaf utilisation. Compound bin-ID gives 3× speedup at zero cost.

Flower is incompatible with SecAgg — and produces bloated models

Concatenation ≠ summation: SecAgg's zero-sum masks cannot cancel. Flower trains on $N/K$ samples per tree → needs ~$K imes$ more trees for equivalent accuracy. No global gradient signal → no principled stopping criterion.

Training overhead is the price; inference is free

11× CatBoost training time (52 min) reflects 7 SecAgg rounds per tree × 5 clients. Inference: ~5 µs/transaction — well within real-time SLAs. DP is a one-line extension; costly at extreme imbalance ($w_+=10$, $\Delta_2 \approx 106$).
